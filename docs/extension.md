# Расширение Lader для Edge: как запустить и как пользоваться

Расширение даёт всё, что умеет окно Lader, прямо в браузере:

- кнопку «Скачать» на страницах YouTube и X;
- пункт «Скачать через Lader» в контекстном меню;
- боковую панель с выбором качества, формата и папки;
- очередь загрузок.

Кратко об устройстве — от этого зависит порядок установки:

| Часть | Где лежит | Что делает |
|---|---|---|
| Расширение | папка `extension/` | интерфейс: панель, кнопки на страницах и меню |
| Помощник `lader-host` | `src/bin/lader-host/`, после сборки — `lader-host.exe` | скачивает видео. Расширение само запускать программы не может, поэтому работу делает помощник |

Edge запускает помощник сам, когда он нужен (открыта панель или идёт загрузка), и закрывает его после трёх минут простоя. Помощник собран из того же ядра, что и приложение Lader. Поэтому многопоточная загрузка, обложки, архив скачанного и компоненты работают одинаково. Компоненты (yt-dlp, Deno, ffmpeg) у расширения и приложения общие — повторно их качать не нужно.

---

## 1. Первый запуск

При установке готового релиза на Windows помощник регистрируется автоматически. Шаг 1 нужен только для запуска из исходников.

### Шаг 1. Зарегистрировать помощник (только из исходников)

1. Если `lader-host.exe` ещё нет в корне проекта, соберите его:

   ```
   cargo build --release --bin lader-host
   ```

   Готовый файл появится в `target\release\lader-host.exe`. Команда `make host` делает то же самое и копирует файл в корень проекта.

2. Дважды щёлкните `D:\Projects\YouTubeDream\lader-host.exe`. Откроется окно консоли, где помощник напишет, что сделал:
   - **скопировал себя** в `%LOCALAPPDATA%\Lader\host\lader-host.exe`. Именно эта копия будет работать, поэтому файл в папке проекта потом можно пересобирать и перемещать;
   - **прописался в реестре** для Edge, Chrome и Chromium. Пишется только в раздел текущего пользователя (HKCU), права администратора не нужны;
   - **перечислил разрешённые расширения**: по умолчанию одно, с ID `kimlopaoiianjkblnjfakfjjilaojkjc`.

3. Нажмите Enter, чтобы закрыть окно.

### Шаг 2. Установить расширение в Edge

**Готовый релиз — без режима разработчика.** Если раньше Lader был загружен
как распакованное расширение, сначала удалите его на `edge://extensions`.
Скачайте **один файл** `lader-extension_*-setup.exe` из опубликованного релиза
и запустите его от имени администратора. NSIS-установщик сам регистрирует
помощника и адрес `updates.xml` для Edge, а Edge скачивает и устанавливает CRX
из релиза по HTTPS. Отдельно скачивать `lader-host.exe` не нужно. Перезапустите
браузер и подтвердите установку, если Edge её предложит. Режим разработчика не нужен.

Для проверки ID откройте `edge://extensions`: должно быть указано
`kimlopaoiianjkblnjfakfjjilaojkjc`. Закрепите значок: кнопка «Расширения»
(кусочек пазла) → значок «глаза» напротив Lader.

Новые версии расширения Edge получает автоматически через GitHub Pages и
Releases. Чтобы обновить помощника, запустите установщик из нового релиза.
Собственный постоянно работающий сервер не нужен, но само автообновление
офлайн работать не может: GitHub должен быть доступен по HTTPS.

**Для разработки из исходников.** Откройте `edge://extensions`, включите
**«Режим разработчика»**, нажмите **«Загрузить распакованное»** и выберите
папку `D:\Projects\YouTubeDream\extension`. В этом варианте ID тот же, поскольку
он задан полем `key` в `manifest.json`. Папку `extension` не удаляйте и не
перемещайте: Edge загружает расширение прямо из неё.

### Шаг 3. Открыть панель

Нажмите значок Lader — справа откроется боковая панель. Если панель пишет «Нужен помощник Lader», повторно запустите установщик или зарегистрируйте помощника вручную по шагу 1.

Если yt-dlp, Deno или ffmpeg ещё не установлены, панель предложит поставить их одной кнопкой. Если они уже есть в системе или их поставило приложение Lader, панель найдёт их сама.

## 2. Как пользоваться

### Скачать видео

Подходит любой из способов:

- **Кнопка «Скачать» на странице.** На YouTube она стоит под видео рядом с названием канала, в шапке канала или плейлиста, а на Shorts плавает поверх ролика. В X кнопка есть у твитов с видео. Нажатие открывает панель уже с этой ссылкой.
- **Правый клик** по ссылке на видео или по самой странице YouTube или X → **«Скачать через Lader»**.
- **Вручную.** Откройте панель, вставьте ссылку в поле на вкладке «Скачать» и нажмите «Получить».

Дальше всё как в приложении:

- **Одно видео:** выберите качество, формат (MP4, WebM, MKV или только звук в MP3/M4A) и папку, затем нажмите «Скачать».
- **Плейлист или канал:** отметьте нужные видео («Выбрать все» / «Снять все», «Загрузить ещё» подгружает следующие). Затем выберите качество, формат и папку и нажмите «Скачать».
- **Видео, открытое из плейлиста:** над ним будет ссылка «Открыть весь плейлист».

### Загрузки

Вкладка **«Загрузки»** — это очередь. Видео качаются строго по одному, как в приложении. Для каждой загрузки видны ход и скорость, её можно отменить. Готовую можно открыть в папке, сорвавшуюся — повторить. Кнопка «Очистить завершённые» убирает лишнее.

Если закрыть браузер посреди загрузки, помощник отменит её и удалит недокачанное. В списке она останется с кнопкой «Повторить».

### Настройки

Кнопка с шестерёнкой в панели:

| Настройка | Что значит |
|---|---|
| Корневая папка загрузок | Куда качать. Пока не задана, берётся «Целевая папка» из приложения Lader (у вас `D:\Downloader`). Внутри неё создаются папки каналов |
| Cookies | «Без cookies», «Этот браузер (Edge)» или другой браузер — см. ниже |
| Потоков на файл | Во сколько соединений качать (по умолчанию как в приложении) |
| Кнопка «Скачать» на страницах YouTube и X | Показывать ли кнопку на сайтах |
| Компоненты: yt-dlp, Deno, ffmpeg | Версии, установка, проверка обновлений — тот же экран, что в приложении |

### Cookies: возрастные, приватные и «чувствительные» видео

Такие видео yt-dlp скачивает только с cookies залогиненного пользователя. Выберите в настройках **«Этот браузер (Edge)»**:

1. Перед каждым запросом расширение берёт у Edge cookies доменов youtube.com, x.com и twitter.com.
2. Помощник кладёт их во временный файл.
3. Файл удаляется сразу, как только yt-dlp закончил.

Это единственный рабочий способ для Edge и Chrome. С 2024 года они шифруют свою базу cookies так, что сторонняя программа её не прочитает. Поэтому вариант «Edge» или «Chrome» в самом приложении Lader, скорее всего, не сработает. Firefox и остальные браузеры передаются yt-dlp как раньше.

## 3. После изменений в коде

| Что поменяли | Что сделать |
|---|---|
| Файлы в `extension/` | На `edge://extensions` нажмите «Обновить» (круглая стрелка) на карточке Lader. Открытые вкладки YouTube и X перезагрузите, чтобы обновились кнопки на страницах |
| Rust-код помощника (`src/bin/lader-host/` или общее ядро `src/`) | Пересоберите (`cargo build --release --bin lader-host` или `make host`) и снова запустите `lader-host.exe` двойным щелчком. Он заменит свою копию в `%LOCALAPPDATA%\Lader\host`, даже если браузер прямо сейчас держит старую. Затем закройте и откройте панель: если помощник был запущен, браузер начнёт пользоваться новой копией при следующем запуске помощника — после 3 минут простоя или перезапуска Edge |
| `extension/manifest.json` | Как для файлов расширения. Если менялся `key`, изменится ID — см. раздел 4 |

Приложение `lader.exe` и помощник не зависят друг от друга: пересборка одного не требует пересборки другого.

## 4. Если что-то не работает

| Что видно | Причина и решение |
|---|---|
| «Нужен помощник Lader» | Помощник не зарегистрирован. Запустите `lader-host.exe` (раздел 1, шаг 1) и нажмите в панели «Проверить снова» |
| «Помощник не запустился» / «Помощник не отвечает» | Зарегистрированный файл переместили или удалили. Снова запустите `lader-host.exe` — он зарегистрируется заново |
| «Помощник не разрешает это расширение» | У расширения другой ID, чем тот, что разрешён помощнику: например, оно установлено из магазина или ключ в манифесте другой. Панель покажет нужную команду и кнопку «Скопировать команду». Выполните её в терминале в папке с помощником: `lader-host --install --extension-id <ID>` |
| Нет кнопки «Скачать» на YouTube или X | Перезагрузите вкладку. Проверьте настройку «Кнопка „Скачать“ на страницах». Если YouTube поменял вёрстку, кнопка может временно не находить место — пользуйтесь значком или контекстным меню |
| Ошибки загрузки | Те же, что в приложении. Сначала откройте «Компоненты» и обновите yt-dlp. Для закрытых видео включите cookies «Этот браузер (Edge)» |

**Где смотреть журналы.** На `edge://extensions`, в карточке Lader, ссылка **«service worker»** открывает консоль фоновой части: там видно подключение к помощнику и его ошибки. Консоль самой панели открывается правым кликом внутри неё → «Проверить».

**Проверить регистрацию вручную.** В PowerShell:

```
reg query "HKCU\Software\Microsoft\Edge\NativeMessagingHosts\io.github.grandlaite.lader"
Get-Content "$env:LOCALAPPDATA\Lader\host\io.github.grandlaite.lader.json"
```

Первая команда должна показать путь к JSON-файлу, вторая — путь к `lader-host.exe` и список разрешённых расширений.

## 5. Удаление

1. На `edge://extensions` нажмите «Удалить» у Lader. Если расширение было
   установлено через NSIS, также удалите **«Lader — расширение Edge»** в
   «Параметры → Приложения → Установленные приложения»: это уберёт его
   регистрацию внешнего расширения, но не затронет приложение Lader.
2. Снимите регистрацию помощника:

   ```
   "%LOCALAPPDATA%\Lader\host\lader-host.exe" --uninstall
   ```

   После этого папку `%LOCALAPPDATA%\Lader\host` можно удалить.
3. Компоненты (`%LOCALAPPDATA%\Lader\bin`) и настройки (`%APPDATA%\Lader`) общие с приложением. Удаляйте их, только если не пользуетесь и приложением.

## 6. Выпуск для других

Обычный релиз (тег `v*`, см. README → «Выпуск версии») сам собирает для черновика релиза:

- `lader-extension_<версия>.zip` — архив для разработки;
- `lader-extension_<версия>.crx` — подписанное расширение для Edge;
- `lader-extension_<версия>-setup.exe` — единый NSIS-установщик расширения и Windows-помощника;
- отдельный `lader-host.exe` для ручной переустановки, `lader-host_macos` и `lader-host_linux_x64`.

GitHub Pages публикует `updates.xml`, указывающий на CRX в релизе. До первого
выпуска настройте секрет `LADER_EXTENSION_KEY` и GitHub Actions как источник
Pages по инструкции в README. В секрете нужен PEM именно того закрытого ключа,
который соответствует текущему ID. Новый ключ меняет ID, поэтому его нельзя
использовать для обновления уже установленных копий. После проверки черновика
обязательно опубликуйте релиз: скачивание CRX и обновления через GitHub
требуют доступа в интернет.

Перед тегом поднимите версию **в двух местах**: `version` в `Cargo.toml` и `"version"` в `extension/manifest.json`. Workflow проверяет, что они совпадают.

Локально архив расширения собирается командой `make extension`. Ей нужна утилита `zip`; если её нет, подойдёт PowerShell:

```
Compress-Archive -Path extension\* -DestinationPath lader-extension.zip -Force
```

Для локальной сборки CRX, `updates.xml` и NSIS-установщика нужны Edge, Node.js
и NSIS (`makensis` в PATH или флаг `--makensis`). PEM указывается явно:

```
make extension-external LADER_EXTENSION_KEY=/path/to/lader-extension.pem
```

Не добавляйте PEM в Git. Готовые файлы появятся в `target/extension/`.

Пользователю нужен `*-setup.exe` из раздела 1; ZIP предназначен для загрузки
распакованного расширения при разработке. Расширение, опубликованное в магазине Edge Add-ons, получит другой ID — тогда помощник регистрируют командой `lader-host --install --extension-id <ID>` (панель её подскажет).

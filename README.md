# Lader

Десктопное приложение на Rust + [Slint](https://slint.dev) для Windows, macOS
и Linux: скачивает видео с YouTube и X (Twitter) через
[yt-dlp](https://github.com/yt-dlp/yt-dlp).

Поддерживает:
- одиночные видео по ссылке — YouTube (`watch?v=`, `youtu.be`, Shorts, Live)
  и твиты с видео (`x.com/…/status/…`, `twitter.com/…/status/…`)
- каналы и плейлисты YouTube — список с чекбоксами, превью и постраничной
  загрузкой; ссылка на корень канала (`youtube.com/@канал`) открывает его видео
- выбор качества и формата: MP4, WebM, MKV или только звук в MP3/M4A
- обложку внутри mp4/m4a/mp3 и архив уже скачанного: повторная загрузка
  пропускает то, что уже есть в папке
- cookies из браузера для видео, закрытых авторизацией или возрастным
  ограничением

Всё это есть и в виде расширения для Microsoft Edge, подробности в разделе
[«Расширение для Microsoft Edge»](#расширение-для-microsoft-edge).

## Компоненты: yt-dlp, Deno, ffmpeg

Приложению нужны три программы:

| Компонент | Зачем | Откуда | Объём |
|---|---|---|---|
| yt-dlp | скачивает видео | [GitHub yt-dlp](https://github.com/yt-dlp/yt-dlp/releases) | ~18 МБ |
| Deno | без него yt-dlp не может разобрать YouTube | [GitHub Deno](https://github.com/denoland/deno/releases) | ~40 МБ |
| ffmpeg | склейка видео со звуком, MP3, обложки | Windows/Linux — [сборки yt-dlp](https://github.com/yt-dlp/FFmpeg-Builds/releases); macOS — [Martin Riedl](https://ffmpeg.martin-riedl.de) | 56–150 МБ |

Как лаунчер игры ставит себе Java, приложение ставит их само:

1. При первом запуске показывает экран «Подготовка к работе» со списком того,
   чего не хватает, и кнопкой **«Установить всё»**. Если в системе уже есть
   свои yt-dlp, Deno или ffmpeg (в `PATH`), они используются, и скачивать их
   не нужно.
2. Каждый файл скачивается с официальной страницы проекта и сверяется с
   контрольной суммой SHA-256, которую проект публикует рядом. Затем новая
   программа пробно запускается, и только после этого подменяет рабочую
   копию. Сломанная загрузка не оставит приложение без компонента.
3. Если нажать «Получить» или «Скачать», когда чего-то не хватает, сначала
   откроется экран компонентов. После установки запрос продолжится сам.
4. yt-dlp при запуске и затем раз в сутки сверяется с последним релизом. Если
   вышла новая версия, появляется баннер с кнопкой **«Обновить»**. Если
   загрузка упала на устаревшей версии, в окне ошибки есть кнопка
   **«Обновить yt-dlp и повторить»**.

Экран компонентов можно открыть кликом по строке статуса справа вверху.
Там видно, какие версии стоят и откуда, и можно переустановить любой компонент.

Свои копии лежат в папке данных пользователя (таблица ниже). Что установлено,
записано в `components.json` рядом с ними. В системе ничего не меняется:
`PATH` и реестр приложение не трогает, а пути к программам передаёт yt-dlp
напрямую. Деинсталлятор Windows предлагает удалить и эту папку.

## Многопоточная загрузка

Как Steam, Lader качает каждый файл в несколько соединений сразу — число
выбирается в поле **«Потоков»** (1, 2, 4, 8 или 16; по умолчанию 8). Канал
делится между соединениями, а не между программами, поэтому несколько
соединений обходят ограничения сервера на одно соединение и забирают
бо́льшую долю общего канала.

Загрузчик свой (`src/fetch.rs`), по мотивам aria2 — идеи, не код:

- файл делится на диапазоны по ходу загрузки: освободившееся соединение
  делит пополам самый большой ещё не скачанный диапазон и забирает вторую
  половину, так быстрые соединения выручают медленные;
- маленькие файлы (меньше 4 МБ) не дробятся; один запрос — не больше 10 МБ
  (YouTube режет длинные запросы);
- зависшее соединение (30 с без данных) снимается, его остаток забирают
  другие; ошибки повторяются с нарастающей паузой.

С yt-dlp это работает так: yt-dlp выбирает форматы и отдаёт прямые ссылки
(`-j`), Lader скачивает дорожки под теми именами, которые ждёт yt-dlp,
а склейку, обложку и архив yt-dlp делает сам по сохранённому описанию
(`--load-info-json`). Фрагментированные видео (HLS у X) yt-dlp качает в
столько же потоков сам. Если ускоренный путь не подходит или сорвался,
работает обычная загрузка yt-dlp. Тем же загрузчиком ставятся компоненты.

Чем больше потоков, тем сильнее загрузка теснит остальных в сети (звонки,
игры); слишком много соединений YouTube может посчитать подозрительными —
поэтому больше 16 выбрать нельзя.

## X (Twitter)

Вставляйте ссылку на конкретный твит: `x.com/username/status/1234567890`.
Ленту профиля целиком выгрузить нельзя: у yt-dlp нет для неё экстрактора,
поддерживаются только отдельные твиты.

Часть роликов на X доступна только залогиненным пользователям (приватные
и «чувствительные» твиты). Для них выберите свой браузер в поле
**«Cookies из браузера»** — приложение передаст их в yt-dlp через
`--cookies-from-browser`. Если ссылка не открывается без авторизации,
окно ошибки само подскажет это сделать.

## Расширение для Microsoft Edge

Всё, что умеет окно Lader, доступно прямо в браузере. Расширение ставит кнопку
«Скачать» на страницы видео, Shorts, плейлистов и каналов YouTube и к твитам с
видео в X, добавляет пункт «Скачать через Lader» в контекстное меню ссылок и
открывает боковую панель с теми же экранами, что у приложения. В панели
выбираются качество и формат (MP4, WebM, MKV, MP3 или M4A), папка, нужные видео
канала или плейлиста с постраничной подгрузкой. Загрузки идут очередью, их ход
виден на вкладке «Загрузки».

Само расширение запускать программы не может, поэтому работу делает небольшой
помощник `lader-host`. Edge запускает его через Native Messaging, когда открыта
панель или идёт загрузка, и закрывает после трёх минут простоя. Помощник собран
из того же ядра `lader_core`, что и приложение, поэтому многопоточная загрузка,
обложки внутри файлов, архив скачанного, подсказки при ошибках и установка
yt-dlp, Deno и ffmpeg работают точно так же. Компоненты у них общие и лежат в
одной папке, второй раз качать их не нужно.

Пошаговая инструкция — запуск из исходников, работа с панелью, обновление
после правок кода, решение проблем и удаление — в [docs/extension.md](docs/extension.md).

### Установка

1. Скачайте из опубликованного релиза **один файл**
   `lader-extension_*-setup.exe` и запустите его от имени администратора.
   Установщик NSIS сам зарегистрирует помощника и адрес обновления расширения,
   а Edge скачает расширение по HTTPS. **Режим разработчика не нужен.** Если
   Lader раньше был загружен как распакованное расширение, сначала удалите его
   на `edge://extensions`.
2. Перезапустите Edge и нажмите значок Lader на панели инструментов. Если
   yt-dlp, Deno или ffmpeg ещё не установлены, панель предложит поставить их
   одной кнопкой.

Расширение будет получать новые версии через GitHub Pages и Releases. Чтобы
обновить помощника, запустите установщик из нового релиза. Отдельный
`lader-host.exe` оставлен для ручной переустановки; на macOS и Linux его нужно
запустить самостоятельно. ZIP в релизе предназначен для разработки:
распакуйте его в постоянную папку, включите режим разработчика и нажмите
«Загрузить распакованное».

Из исходников помощник собирается командой `make host` (или
`cargo build --release --bin lader-host`), архив расширения командой
`make extension`. На macOS и Linux помощник регистрируется так же, запуском
без аргументов из терминала.

ID расширения постоянный, `kimlopaoiianjkblnjfakfjjilaojkjc`. Его задаёт поле
`key` в `extension/manifest.json`, и именно его помощник разрешает по
умолчанию. У расширения, опубликованного в магазине Edge Add-ons, ID будет
другим. Тогда помощник нужно зарегистрировать ещё раз с этим ID (панель сама
покажет нужную команду).

```
lader-host --install --extension-id <ID>
lader-host --uninstall
```

### Cookies в расширении

Видео с возрастным ограничением, приватные и «чувствительные» твиты yt-dlp
скачивает только с cookies. С 2024 года Edge и Chrome шифруют базу cookies
ключом, привязанным к самому браузеру, и `--cookies-from-browser edge` больше
не работает. Расширение обходит это штатно. Если в настройках выбрано «Этот
браузер (Edge)», перед каждым запросом оно берёт у браузера cookies доменов
youtube.com, x.com и twitter.com, помощник кладёт их во временный файл для
`--cookies` и удаляет его сразу, как только yt-dlp закончил. Firefox и другие
браузеры по-прежнему передаются через `--cookies-from-browser`.

### Как устроено

| Файл | Назначение |
|---|---|
| `extension/manifest.json` | Manifest V3, боковая панель, Native Messaging, cookies, контекстное меню |
| `extension/background.js` | единственное соединение с помощником, список загрузок, значок |
| `extension/panel.*` | интерфейс (ссылка, видео, список канала, загрузки, компоненты, настройки) |
| `extension/content/` | кнопки «Скачать» на страницах YouTube и X |
| `src/bin/lader-host/` | помощник (протокол, очередь, cookies, регистрация в браузерах) |

Расширение и помощник обмениваются сообщениями JSON, формат описан в начале
`src/bin/lader-host/host.rs`. Видео качаются строго по одному, как в
приложении. Если закрыть браузер посреди загрузки, помощник отменит её и
удалит недокачанное, а в списке загрузок она останется с кнопкой «Повторить».

## Сборка

Нужен [Rust](https://rustup.rs) (stable, 1.88+). На Linux ещё пакеты для
Slint: `pkg-config libfontconfig1-dev libxkbcommon-dev libwayland-dev`.

```
cargo build --release
```

Готовые файлы — `target/release/lader(.exe)`, `target/release/embed-thumbs(.exe)`
и помощник расширения `target/release/lader-host(.exe)`.
`make build` собирает их и копирует в корень проекта. В релизной сборке
окно консоли не появляется.

Тесты: `cargo test`. Тесты, которые ходят в сеть (адреса и контрольные суммы
компонентов, установка yt-dlp, превью YouTube), запускаются отдельно:
`cargo test -- --ignored`.

## Выпуск версии

Установщики собирает GitHub Actions ([release.yml](.github/workflows/release.yml))
с помощью [cargo-packager](https://github.com/crabnebula-dev/cargo-packager).
Его настройки лежат в `[package.metadata.packager]` в `Cargo.toml`.

Перед первым выпуском внешнего расширения один раз настройте репозиторий:

1. **Settings → Secrets and variables → Actions → New repository secret**:
   добавьте `LADER_EXTENSION_KEY` с полным PEM закрытого ключа расширения,
   включая строки `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----`.
   Это должен быть ключ, соответствующий `key` в `extension/manifest.json` и ID
   `kimlopaoiianjkblnjfakfjjilaojkjc`, иначе сборка остановится с ошибкой.
   Храните резервную копию ключа отдельно: без него нельзя выпускать обновления
   с тем же ID. Новый ключ означает новое расширение для пользователей.
2. **Settings → Pages → Build and deployment → Source**: выберите **GitHub
   Actions**. Workflow опубликует `updates.xml` на GitHub Pages. Своё
   постоянно работающее серверное ПО для этого не требуется.

Затем для каждого выпуска:

1. Поднять `version` в `Cargo.toml` и `"version"` в
   `extension/manifest.json`, затем закоммитить.
2. `git tag v2.1.0 && git push origin v2.1.0` — номер тега должен совпадать
   с версией в `Cargo.toml`.
3. Через ~15 минут на GitHub появится черновик релиза с установщиками для
   трёх ОС, CRX и NSIS-установщиком расширения. Проверьте его и нажмите
   **Publish release**: Edge не сможет скачать CRX из неопубликованного
   черновика. Автообновление расширения получает только новые версии
   расширения; `lader-host` обновляется отдельно.

Ручной запуск workflow (Actions → Release → Run workflow) только собирает
установщики в артефакты запуска, релиз при этом не создаётся. Тесты на трёх
ОС при каждом push запускает [ci.yml](.github/workflows/ci.yml).

Иконки — `packaging/icons/`: пиксель-арт 32×32 (`lader-32.png`), увеличенный в целое число раз без сглаживания.
Русский перевод установщика — `packaging/nsis/Russian.nsh`.

## embed-thumbs

Утилита для уже скачанных папок: рекурсивно встраивает превью из `_thumbs/`
(или лежащие рядом с файлом) в mp4/m4a/mp3 как обложки. В установщики не
входит, собирается вместе с приложением.

```
embed-thumbs "D:\YT\МойКанал"
embed-thumbs --dry-run "D:\YT"
```

## Где что хранится

| Что | Windows | macOS | Linux |
|---|---|---|---|
| Настройки | `%APPDATA%\Lader\settings.json` | `~/Library/Application Support/Lader/settings.json` | `~/.config/Lader/settings.json` |
| Компоненты и `components.json` | `%LOCALAPPDATA%\Lader\bin` | `~/Library/Application Support/Lader/bin` | `~/.local/share/Lader/bin` |
| Отчёт о падении | `%LOCALAPPDATA%\Lader\crash.log` | `~/Library/Application Support/Lader/crash.log` | `~/.local/share/Lader/crash.log` |
| Помощник расширения | `%LOCALAPPDATA%\Lader\host` | `~/Library/Application Support/Lader/host` | `~/.local/share/Lader/host` |

При первом запуске настройки и скачанные компоненты переносятся из папок прежнего имени
(`YouTubeDream`), а настройки самой первой, Fyne-версии — из её файла настроек.
